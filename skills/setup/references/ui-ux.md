# UI / UX 模板

用于用户如何理解和操作产品，保存在 `docs/05-ux-ux.md`。已有设计文档经批准迁移，保留设计依据、交互细节和当前开发要求。命令行或 API 产品按其交互界面调整，不凭空添加图形界面要求。

```markdown
# 使用体验与设计

## 设计依据
<当前设计稿、既有组件、设计令牌或接口规范；标明适用范围与维护源。>

## 核心使用流程
<主要任务的入口、当前对象、关键动作、结果及下一步；业务规则引用需求文档。>

## 状态与反馈
<适用的加载、空结果、成功、失败、禁用和权限不足；取消、重试与恢复的反馈。>

## 呈现与交互约束
<视觉、文案、布局、目标设备、键盘与无障碍要求；或 CLI/API 的输入输出、错误与兼容约定。>

## 体验验收标准
<核心任务可完成、反馈可理解；长内容、异常数据和目标环境仍可用。具体检查方法引用测试文档。>
```

完成标准：有可辨认的设计依据和可观察的体验要求；不以“美观”“易用”代替判据，不把截图或构建通过当成操作通过。

不足时：从已确认的用户场景补失败与恢复体验，缺失的设计选择先确认；实现与设计不符时区分待修复和已批准变更。保留项目设备与风格约束，复杂页面细节拆到独立设计说明并添加路由。
