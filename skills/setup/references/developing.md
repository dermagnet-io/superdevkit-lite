# 开发约定模板

用于环境、实施和交付中的项目特定要求，保存在 `docs/06-developing.md`。验证方法归入 `docs/07-testing.md`；从原章节拆分时先批准方案并保留全部相关内容及引用。

```markdown
# 开发约定

## 环境与启动
<工具链事实的配置来源、安装 / 启动入口、执行目录、必要环境与预期结果；秘密只写变量用途。>

## 工作范围与登记
单项需求文档保存在 docs/specs/，产品总体目标维护在 docs/01-product-requirement.md。
<工作票和计划的实际位置；复用已有需求与工作，独立范围如何登记及拆分。>
<分支基线、工作区复用与隔离、受保护路径及数据边界，按项目实际要求填写。>

## 实施与验证
<项目特定的接口、兼容性、依赖和质量约束；路由到适用的验证与体验标准。>
<可自主完成的工作及需要确认的产品取舍、范围变化或外部操作；沿用已有有效授权。>

## 交付与完成
<交付物、可运行 / 可审阅入口、证据和限制的记录位置。>
<合并、发布或部署的实际终点与授权条件；工作状态更新及资源保留 / 清理规则。>
开发任务的最终回报遵循 Lite finalize 的格式；项目补充实际验收入口和必要证据位置，详细记录通过链接提供。讨论会话不套用交付格式。

## 文档维护
| 本次变化 | 更新位置 |
|---|---|
| 产品范围或用户行为 | <产品文档与相应 spec> |
| 模块、接口或数据边界 | <架构或扩展文档> |
| 重要取舍 | <简短决策记录及当前规则所在文档> |
| 阶段与交付状态 | <路线图，引用工作记录> |
| 交互、视觉或体验标准 | <UI / UX 文档及设计源> |
| 环境、工程或验证方式 | <开发 / 测试文档> |
<交付时检查相关文档影响；路径、标题和规则变化同步入口，无影响时不制造更新。>
维护优先整理格式、分组和补充说明，保留项目事实与当前开发内容；迁移前列出内容去向并获得批准，迁移后核对无遗漏。
```

完成标准：执行者能找到启动、登记、验证和交付依据；完成条件覆盖需求、代码、适用体验、证据与文档同步。实现、测试通过、合并及发布按事实分别说明。

不足时：从脚本和配置核对命令及前提，给现有清单补来源和说明。缺失的项目政策列为建议待确认，不套用其他项目的 tracker、每票分支、审批或部署规则。已使用通用技能时增加能力引用，保留项目特定要求与环境故障经验。长操作手册经批准无损拆分后给出阅读条件，不能因模板未列出而删除当前开发信息。
