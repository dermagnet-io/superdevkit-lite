# Start

在首次修改前核对工作上下文；中断恢复、切换范围或环境变化后，只重查可能过时的事实。查询、诊断、评审或仅拆票不因此升级为实现，也不强制建票或创建工作区。

## 开工判断

- 从当前请求和已有记录确定目标、范围、验收条件与本轮授权终点。已确认的需求直接沿用；仅影响下一步的重要缺口才询问。
- 读取项目治理入口。核对实际仓库、分支或 detached 状态、未提交内容、已有隔离工作区和基线；需要判断远端新旧时实际获取远端状态，不能把本地缓存当最新，也不自动拉取合并或覆盖改动。
- 按项目约定查找相关工作票。已有票核对范围后复用；需要登记的新范围先用 [to-tickets](../to-tickets/SKILL.md)，再开始其实现。项目未要求 tracker 时不强加外部服务；登记受阻时说明缺口，不虚构票号。
- 同一范围且归属明确时复用已有工作区。独立范围按项目隔离规则创建；没有固定规则时，根据并行修改、污染风险与交付边界选择最小隔离。不要因新一轮对话重复建区，也不要把旧票已关闭的分支直接当新任务分支。遇到冲突改动先保留，不自动 stash、重置或删除。
- 启动或修改服务前，核对源码工作区、实际运行版本、端口、进程或容器、数据库与持久数据的归属。代码隔离不等于运行环境隔离；测试不能误用或销毁其他任务的数据。

## 就绪与继续

保留足以恢复工作的简短定位：范围/工作票（或不适用）、分支/工作区、基线、适用环境与授权终点。放在项目已有任务记录中即可，不另建重复账本，不记录 secrets 或业务数据。

本技能是执行约定，不是自动门禁。工具或宿主能力缺失只阻塞依赖它的操作；不声称已建立未安装的检查或停止钩子。完成条件是能明确回答“改哪里、为何可改、如何验证、交付到哪里”，而非机械执行所有工具。就绪后继续已授权实现，不为常规工作区选择重复求批。
