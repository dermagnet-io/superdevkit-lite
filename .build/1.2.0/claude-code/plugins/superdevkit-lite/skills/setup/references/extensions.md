# 扩展文档模板

当某主题需要独立维护或当前文档难以按任务阅读时再拆分。系统级扩展文档放在 `docs/` 根目录，从 08 起按人类阅读顺序编号，例如 `08-deployment.md`；具体主题与后续编号按项目需要安排。AGENTS 添加“何时读取 + 文档用途”，原文档保留上下文和引用。

```markdown
# <部署 / 安全 / 数据治理 / 其他主题>

## 范围与依据
<负责什么、适用于哪些环境；现行约定、代码 / 配置或已确认决定的来源。>

## 必须满足的约束
<该主题特有的不变式、权限与数据边界；区分已实现保护与治理要求。>

## 操作与失败处理
<需要操作时说明入口、前提、作用范围、成功结果、失败停止条件及恢复方式。>

## 验证与维护
<如何核对约束、证据落点；哪些变化需要同步哪些文档与配置。>
```

按主题选择必要内容：

- 部署：目标环境和版本、现有配置与数据保留、更新验证、回退或恢复路径及其已验证范围。
- 安全：数据分类、信任边界、权限、秘密管理、外部依赖和实际检查；不默认赋予合规认证或新增安全承诺。
- 数据：归属、生命周期、迁移、保留、备份与恢复；区分备份存在与恢复已验证。

完成标准：独立阅读者能判断适用范围、约束和操作结果，不依赖散落的矛盾规则。

不足时：补该主题必要的失败和恢复信息，未知要求先确认。拆分列入修订方案，批准后无损迁移并同步所有引用，对照原文确认独有信息无遗漏；写入操作说明不表示获准执行操作。
