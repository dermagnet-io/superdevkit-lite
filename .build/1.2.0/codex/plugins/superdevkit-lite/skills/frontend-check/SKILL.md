# Frontend Check

依据需求和项目设计规范，在运行中的界面实际完成受影响的用户任务。项目路径规则用于识别影响，同时考虑接口或配置变化引起的界面行为变化。

## 验收

- 验证用户能找到入口、理解操作并完成任务；检查成功反馈及相关的加载、空白、错误与恢复状态。
- 按变更影响检查布局、文案、响应速度、键盘操作、焦点、可读性及无障碍语义。
- 覆盖受影响且项目要求支持的视口、角色、语言和主题，不机械穷举无关组合。
- 使用当前环境可用且符合项目要求的浏览器工具。截图用于呈现证据，交互结论必须来自实际操作。
- 实现任务中修复体验问题并复验受影响部分；仅验收任务则报告发现。沿用既有设计，不借验收引入无关改版。

## 证据与完成条件

记录受测版本、环境、场景、操作及结果，必要时附截图。相关内容未变时复用证据。环境、账号或工具不足时说明未验收内容及解除条件，不将静态检查冒充实际体验验收。

受影响流程可用，阻塞体验问题已解决，要求覆盖的场景有真实证据，才可报告验收完成。没有前端体验影响时说明不适用。
