# 路线图模板

用于当前能力与阶段安排，不替代工作票或产品需求，保存在 `docs/04-roadmap.md`。现有阶段、开发计划、阻塞和交付依据必须保留。

```markdown
# 路线图

## 当前状态
<当前可用能力、尚不可用能力及核对日期；区分实现、验证、合入与发布。>

## 阶段与顺序
| 阶段 | 目标 / 范围 | 前置依赖 | 完成条件 | 状态与证据入口 |
|---|---|---|---|---|
| <阶段> | <用户结果> | <实际依赖> | <可核对判据> | <需求 / 工作票 / 交付记录> |

## 下一步与待定事项
<当前重点、阻塞和未确定的优先级；日期只填真实承诺。>
```

完成标准：能判断现在可用什么、下一步做什么及为何，阶段状态有依据。状态名称沿用项目约定，排期不等于实施、上线或外部操作授权。

不足时：通过实际代码、工作登记与交付证据核对状态；证据不够保留待核实。优先级冲突先确认，整理现有记录并补工作票链接，不删除当前计划或尚未完成事项。调整阶段编号时保留历史映射，避免旧需求失去指向。
