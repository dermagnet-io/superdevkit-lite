# 测试与验收模板

用于选择能证明需求的检查，保存在 `docs/07-testing.md`。已有测试章节经批准完整迁入；若该位置已有部署等文档，先列出其从 08 起重新编号的迁移方案，禁止覆盖原内容。

```markdown
# 测试与验收

## 运行前提
<工作目录、必要依赖、测试数据及隔离环境；哪些检查依赖外部服务或设备。>

## 按变更选择检查
| 行为或风险 | 检查入口 / 操作 | 通过条件 | 运行限制 / 未覆盖部分 |
|---|---|---|---|
| <实际适用范围> | <已存在的脚本或验收步骤> | <可观察结果> | <边界> |

## 关键回归与体验
<高价值的正常、失败和边界场景；引用对应需求与体验标准，细节由测试资产维护。>

## 证据与完成
<记录检查对应的代码与环境、命令 / 操作、实际结果及未覆盖项的位置。>
<适用的本地与 CI 判据；区分未执行、失败、通过，以及人工与自动检查。>
```

完成标准：需求能映射到合适的验证入口，覆盖关键行为及失败方向；尚无对应检查时如实记录缺口。验证命令的定义、脚本实际覆盖、CI 运行与分支保护是不同事实。

不足时：补可观察判据、真实运行前提和隔离方式，不以固定测试数量、覆盖率或每次全量代替质量要求。说明什么变化使旧证据失效；无相关变化的有效证据可以复用。前端交互与呈现需要适用的实际操作和视觉检查；数据与接口按风险补持久化、权限、兼容等验证。文档修改只能定义所需检查，新增测试或门禁另列实施工作，不能写成已经具备。
