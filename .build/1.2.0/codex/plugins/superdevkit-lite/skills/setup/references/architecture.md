# 架构模板

用于解释实际系统及其边界，保存在 `docs/02-architecture.md`；小项目可以用少量章节描述，不要求完整目录树或固定架构模式。已有模块、接口、约束和当前开发说明完整保留。

```markdown
# 系统架构

<本页描述的分支 / 版本范围与核对依据；规划内容单独标注。>

## 系统组成
| 模块 / 服务 | 职责 | 关键实现入口 | 依赖与边界 |
|---|---|---|---|
| <模块> | <负责什么> | <少量关键路径> | <允许与禁止的依赖> |

## 关键流程
<代表性请求、任务或事件如何跨模块流转；标出接口、状态与失败传播。图示有助理解时再添加。>

## 数据与信任边界
<数据归属、持久化、权限、不变式、外部系统边界；按实际项目选取。>

## 扩展与约束
<新增能力通常放在哪里、接口兼容与跨层限制；引用相关代码或配置。>

## 现状差距与规划
<约定与实现的偏差、未接通能力及后续工作入口；不得把规划写成已实现。>
```

完成标准：读者能定位修改范围、理解依赖和关键不变式；结构判断能追溯到代码、配置或已确认设计。选型原因未知时明确未知，不能从目录或依赖猜测历史意图。

不足时：补关键边界与流程，整理现有清单的分组、格式与配置来源，保留项目细节及原因。实际违反约定时报告实现缺口，不能直接把违规行为改写为允许。复杂的部署、安全或数据细节经批准可无损拆出并更新 AGENTS 路由；本页保留系统关系及引用。
