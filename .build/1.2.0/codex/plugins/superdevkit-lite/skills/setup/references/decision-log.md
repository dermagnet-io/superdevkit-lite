# 精简决策日志模板

保存在 `docs/03-decision-log.md`。新增条目记录已确认且影响产品范围、架构、约束或质量标准的重要取舍；当前规则在所属文档维护。

```markdown
# 决策日志

<当前规则入口；有历史归档时提供链接。>

## D-<编号> · <简短标题>
<日期> · <有效 / 被 D-xxx 替代 / 撤销>：<一句话决定。>
理由：<关键原因或取舍，一句话；需要时链接确认来源或详细需求。>
```

新增条目通常 2–4 行，包含日期、决定、关键理由与状态；标题用于稳定定位。详细需求讨论放 `docs/specs/` 中对应记录，设计依据链接原文。新增决策不记录普通修复、任务进度、完整访谈或未经确认的建议；旧记录不因不符合新格式而删除。

完成标准：能迅速找到有效结论及依据，被替代的规则不会被误用。

不足时：给长条目增加简短摘要，保留现有详细依据；新决定标明替代关系，并同步当前规则。历史过多时提出归档方案，经批准保留全文到归档中，主文档保留有效决定、摘要和必要跳转。保持原编号、锚点及引用可达，必要时在旧位置留短跳转；不为了连续编号重排历史，不为缩短日志删减当前开发所需的决定与背景。
