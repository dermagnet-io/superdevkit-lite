# SuperDevKit Lite

读取当前任务及项目治理入口中适用的路由、约束和交付约定。只加载当前阶段需要的技能，不预先读取全部技能或项目文档。

先判断任务意图：普通讨论、解释和只读查询默认不进入开发流程；明确要求实现、修复或修改时从下表选择适用阶段。用户明确点名技能或要求专项工作时只处理该范围。开发中途的提问不取消已有任务；明确暂停或转为讨论时停止后续实施。

| 当前工作 | 技能 |
|---|---|
| 接入项目或检查、补充系统级治理文档 | [setup](../setup/SKILL.md) |
| 首次实现、切换范围或恢复后上下文可能变化 | [start](../start/SKILL.md) |
| 开发需求仍需确认，或明确要求深入需求访谈 | [grill-to-spec](../grill-to-spec/SKILL.md) |
| 已确认需求，需要登记与拆分工作 | [to-tickets](../to-tickets/SKILL.md) |
| 代码评审或实现验证 | [verify](../verify/SKILL.md) |
| 前端流程、交互或呈现受影响 | [frontend-check](../frontend-check/SKILL.md) |
| 验证后完成约定交付 | [finalize](../finalize/SKILL.md) |

已明确的需求和已有工作票直接沿用。开发任务按项目约定从当前阶段继续，直到达到交付终点；只读查询、仅评审或仅拆票请求保持原范围，不自动扩展为实现或发布。

实现前完成 start 的上下文核对；需求发生变化时判断属于原票补充还是独立范围，不等到提交时才登记。验证和交付分别进入对应技能，不能只读取入口就声称已完成它们。继续同一任务不重复初始化，已有证据按相关内容是否变化判断有效性。

具体文档、工作登记位置、验证命令和交付路径取自项目约定。缺少必要信息时先完成可独立推进的部分，只询问影响下一步的缺口，不创造固定绑定或初始化要求。
