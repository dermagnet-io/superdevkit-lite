# Finalize

读取项目约定的交付终点与当前授权，完成本次范围内的代码交付。没有明确终点时交付可审阅的本地变更，说明尚未执行的外部步骤。

## 交付

- 核对需求与工作票的验收条件、代码验证及适用的前端验收结果。复用仍有效的证据，只补缺失或受变更影响的检查。
- 检查本轮是否使产品、架构、工程或部署文档过时，按项目指定位置同步；无影响时说明不适用，不机械新增报告。
- 检查最终差异与提交范围，保护用户已有改动，清理本次临时调试内容；项目要求的生成物同步交付。
- 按项目约定完成提交、构建产物或变更请求。外部写入遵守已有授权范围，未授权时先准备可审阅内容。
- 集成冲突或修复后验证新的受影响内容；不把集成前的结果直接当作集成后的证据。
- 更新工作票的真实状态，按项目规则关联交付物；代码完成、已提交、已合并和已部署分别报告。
- 合并前核对实际待合入内容及对应提交的适用 CI；合并后核对目标分支实际版本。部署任务另外核对部署版本和目标环境的必要验收，不能用进程健康代替登录或受影响用户流程。只报告已达到的阶段。
- 遗留失败或未验收项明确阻塞性、后续归属及解除条件，按项目要求关联跟踪记录。披露缺口不等于验收通过；只有项目或用户允许延期的非阻塞项才能随本轮交付，不自动关闭未满足条件的票。
- 核对本轮启动的进程、临时代理、测试数据、产物与工作区的去向。保留供用户使用的预览时说明来源和恢复方式；停止时先恢复仍被使用的访问链路。只清理归属明确且获授权的临时内容，清理受阻不影响独立交付，但须留下状态。
- 默认保留工作区，不擅自删除分支、用户文件或改写远程历史。

最终说明交付了什么、在哪里、如何验证、还缺什么。需要后续接手时引用需求、票和证据，补充必要的未记录信息。

完成条件：达到约定交付终点，状态与证据一致。确实受阻时交付已完成部分并说明解除条件，不虚报完成，也不在仍可推进时提前停止。
