# To Tickets

读取已确认需求及项目的工作登记约定，将需求转为一张或多张可实施的票。已有票先核对并复用，避免重复登记。

## 拆分

- 能独立实现、验证和交付的需求只开一张票，不为数量拆分。
- 较大需求按完整用户行为或可验证结果切分，避免只按技术层分票。
- 每张票写明目标、需求来源、验收条件、修改范围、非目标、验证方式及阻塞依赖。
- 必要迁移或重构作为明确工作项，保持中间状态可用；不顺手增加需求。
- 核对全部需求都有归属，依赖无循环，跨票接口明确；不要预写细粒度实现步骤。

## 登记与实施顺序

在项目指定的位置按依赖顺序登记，使后续票能引用真实编号。缺少登记位置时先整理完整票稿，只询问缺失的位置；外部写入缺少授权时先完成可审阅草案，不把草案声称为已发布的票。

输出逐票实施顺序：每张票在实现前核对验收条件与范围，实现后完成相应验证，再更新真实状态。前置条件未满足时，不把依赖它的票视为就绪。拆票请求本身不扩大为实现或发布授权。

完成条件：需求覆盖完整，票可执行且可验证，登记状态和阻塞关系准确；未发布的票稿明确标注。
