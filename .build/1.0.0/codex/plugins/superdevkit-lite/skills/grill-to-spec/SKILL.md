# Grill to Spec

产出可实施、可验收的需求说明。先查相关代码、项目文档和已确认决定，只问无法从现有信息确定的重要问题。

## 需求与确认

- 明确目标用户、要解决的问题、预期行为、范围与非目标。
- 写明适用的兼容性、数据、依赖及修改范围约束；沿用项目已有设计与领域用语。
- 将用户体验纳入验收：怎样完成任务、得到反馈，以及失败后如何恢复。按实际影响覆盖异常路径。
- 只询问会改变产品行为、范围或交付结果的决策。给出具体选项、推荐及取舍；常规实现细节自行判断。
- 用户已明确的要求或已确认的 spec 直接沿用，不重复确认。新增的重要决策在相关实现前确认；等待时继续不依赖答案的调查。

## 产物与完成条件

按项目约定记录目标、需求、约束、非目标及可观察的验收条件，注明确认来源和仍待决定的事项。已有记录以引用为准，不复制多份；未指定落点时先在回复中给出完整说明。

说明修改范围和验证方式，详细程度以接手者能执行为准，不预写完整实现代码。未确认的问题不能伪装成已确认需求，也不应阻塞无关部分。

需求有明确来源，重要决策已确认，约束与验收条件不矛盾，才可进入对应范围的工作拆分。
