# Verify

对照需求、工作票与项目规范检查实际变更，包括本次未提交和新增文件。明确评审范围，不能仅凭实现报告判定完成。

## 评审

- 核对需求是否遗漏、行为是否正确、修改是否越界。
- 按影响检查兼容性、数据完整性、错误处理、安全和可维护性。只扩展调查到能说明的具体风险。
- 发现需引用具体位置，解释触发条件与影响，区分阻塞交付的缺陷和可选改进。
- 实现任务中修复成立的阻塞缺陷；仅评审任务则报告发现，不自行修改。不同意评审意见时提供证据，不为风格偏好扩大重构或擅自改变产品决定。

## 验证与完成条件

- 执行项目规定的适用检查，根据变更风险补足验证。测试检查可观察行为，期望值不能照抄被测实现的计算逻辑。
- 修复 bug 时验证原始症状；可行时让回归用例在修复前失败、修复后通过。
- 不为低影响、可逆变更添加只复述实现的测试。检查通过后，只有相关变化、失败或具体疑点才扩大或重复验证。
- 证据记录命令或操作、受测版本与工作树状态、关键环境及结果。相关代码、依赖或配置变化后重跑受影响检查；单纯进入下一轮对话不使证据失效。
- 区分既有失败、本次回归和环境阻塞。未运行、跳过或范围未覆盖都不能计为通过。

验收条件逐条有证据或明确缺口，阻塞缺陷已解决且适用检查通过，才可报告代码验证完成。自动化通过不等于用户体验已验收。
